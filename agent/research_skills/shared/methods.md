# 研究方法：按需使用

## 数据与范围

优先复用分析报告对应品类的章节、指标、证据和原子分析。记录去重粒度、产品范围、时间、渠道、正文覆盖和版本。商品页联合评论可能含多个SKU，核对 source_product_id 与实际产品映射；不能一律把不同ID删掉，也不能把全部联合评论当作目标型号。

大数据的计数、分组、交叉表由确定性代码完成。已有完整导出时优先用内置 [research_methods](local-methods.md)，在一次 Python 中组合跨批去重、覆盖、分组及引用整理，不把每个统计再变成一次远程调用。标准评论 JSONL 保留所有出现记录；实体统计先全局选 canonical 再筛选，与服务口径一致。渠道原始 payload 可能包含排除项，不混合计数。用模型理解语义、提出标签及研究假设、解释结果；规则全量扫描提供可复算线索，不能冒充语义准确的全量情绪分类。

## 体验、场景和排序

满意与不满可同现于同一高星评论。先看报告的主题与证据，读取影响结论的完整原评、反例及上下文。区分属性提及、正负规则命中、低星关联、评论明确抱怨四种口径。主题可能重叠，不能相加当总人数。

Top 10 若按频次，给出总体、去重单位、分母、分类方法及覆盖；只有定性支持时按影响程度排序并明确依据，不使用虚假的精确人数。某主题不足十项时直说已支持几项。产品质量故障的评论提及率不是实际故障率，不能推算保修/寿命风险。

场景用“谁，在什么环境，为完成什么任务，遇到什么约束，得到什么结果”表达。购买决策按真实叙事连接触发事件、备选方案、取舍条件、最终决定因素、购买后体验；缺失环节不补成虚构旅程。

## 画像与比较

围绕任务、使用约束、平台/电池资产和价值判断分群；年龄、性别、自填身份不能直接证明能力、行为或动机。允许信息不足，不强行归类。需要画像规模时同时区分多标签覆盖和互斥主归属，说明归属优先级及证据强弱；弱证据很多会影响哪些判断，才在正文说明。

跨组比较先查看渠道入口、抽奖激励、使用时长、品类和年份构成。必要时做分层比较或标准化，注明共同层覆盖及剩余不可比因素；标准化不能消除所有偏差，置信区间也不能消除选择偏差。不同含义的运行/充电时长不混算，均值和中位数都不能修复语义混淆。

## 最少的核对

核对关键数字与其对象、分子分母、方向和来源一致，重点检查足以改变产品决策的结论，不增加强制审计流水线。原问题已有充分证据、影响结论的矛盾已处理后即交付；不要为“更完整”继续扩大品牌、渠道、时间、方法或报告格式。剩余不足影响结论时明确写出缺口。抽检用于发现错误，不把“抽10条对8条”称为证明总体精度80%。产品机会应对应真实痛点或约束，区分已证实需求与需要试验验证的假设。
