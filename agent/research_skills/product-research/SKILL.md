# 产品研究

围绕用户要做的判断开展研究，自主选择资料、分析方法、代码与交付形式。参考方法按问题取用，不要求执行固定步骤或固定报告模板。

## 用好分析报告，再融会贯通

分析报告把网评中的体验、场景、动机、问题和质量信息系统提取出来，是产品研究的分析基础。先判断现有范围匹配的报告能回答什么：用 `list_reports` 选择，`get_report_section(section="index")` 定位相关章节，指标、质量和证据工具按需读取。标题不能代替产品、时间、渠道与数据版本核对。

没有合适报告且样本支持时，用 `report_candidates`、`create_report` 创建；服务负责标准计算与等待，报告就绪后读取相关内容。已核实的新采集数据暂未进入报告候选时，可以 `wait_for_report_data`，不循环调用模型等待。分析报告门槛不足时参照[分析维度](../shared/product-dimensions.md)，基于实际原评研究，不扩大产品范围凑门槛。

理解报告各模块之间的关系，对照用户的子问题形成自己的解释与判断。核对会改变结论的矛盾、条件和反例；缺少的分析用原评、聚合统计、原生 Bash/Python/SQL 或允许的联网补齐。不要把报告摘录拼成答案，也不重复计算已经适用的可靠结果。

## 保留独立研究能力

产品范围看商品身份及联合评论池，不能只看 URL slug 或型号文字。普通研究可以复用匹配数据，注明时间；用户明确要求重新采集或最新数据时，完成对应采集或说明缺口，不冒充本轮已更新。采集能力与后台等待说明见[数据与采集](../shared/data-and-collection.md)。

在原生 Bash 中用内置 [research_methods](../shared/local-methods.md) 一次载入完整分片，组合跨批去重、覆盖、计数、分组与引用，再用自由 Python 补充本题分析。优先使用工具给出的 schema、文件和字段路径；只在未知处探索。独立读取同批发出，已有冻结文件直接复用；代码和 Bash 无网络，联网走获准的原生 web 工具。代码负责可重复计算，模型负责语义判断和方法选择，不为每个统计触发一次 LLM，也不添加强制分类或审核流水线。

词法命中、整机星级、语义抱怨与实际故障率是不同指标。保留分子分母、去重粒度、覆盖范围和计算方法。需要语义频次时自行设计并核查分类；只有定性证据时说明排序依据，不制造精确排名。跨产品比较核对共同范围。方法详见[研究方法](../shared/methods.md)。

## 回答与交付

先回答用户问题，再给主要证据、推断和影响决策的缺口。结论引用已读取的来源；原话有可核对的原评。代码输出不自动成为原始事实。完整网评导出的稳定引用方法及文件交付见[交付](../shared/delivery.md)。

原问题的证据已经充分就直接用 DSH 最终回答结束，不为增加完整感扩大研究范围。已完成的分析先交付；另一个采集、报告或格式失败时保留可用成果，说明未完成项，不让用户反复点击继续才看得到正文。
