# 用户研究

目标是理解用户在什么情境下做什么、如何取舍、为何满意或受挫，并为当前产品问题提供判断。网评是观察材料，不能自动等同于总体用户、销量或纵向追踪数据。

## 参考报告提供方法与启发

资料库有 EGO、RYOBI、MILWAUKEE、GREENWORKS 四份用户提供的品牌研究，用户说明其由 Fable 5.1 生成、质量较好。可用 `read_research_reference` 按需读取方法、分群规则、场景、证据与局限；四品牌对比报告可辅助找到共同维度。目录和版本说明见[参考资料](../shared/reference-notes.md)。

重点理解作者如何提出问题、选择分群维度、处理重叠、连接场景和购买决策、识别反例。把适合当前问题的方法融会贯通，不照搬原型名称、统计结论或固定流程。质量较好不表示每个数字、解释与因果均正确；版本绑定的解读注释也是需要理解的知识材料，不是替代判断的答案。

**每个会话都有自己的研究判断。** 先明确本题与底稿在产品、地区、时间、渠道及研究目的上的异同，形成可检验的问题；判断哪些结论可以采用、哪些需要核查、哪些不能迁移。不能仅仅读取报告后转述为新研究。对于概括性问题，不必机械重跑全量分析，但应说明自己的综合判断以及仍待验证的解释。

用户要求“不参考某品牌报告”时，遵守排除范围，不读取、转述或以对比报告迂回引入其结论。仍可基于当前允许的原评独立选择方法。当前任务限定具体产品时，品牌底稿不能替代该产品证据。

## 从证据形成自己的分析

按需要结合分析报告章节、原始评论与当前数据。用任务、情境、约束、已有平台资产、决策动机和价值取舍建立分析框架；不强迫所有评论归类。区分多标签覆盖和互斥主归属、评论条数和独立人数。需要新分群时自主设计假设、检查代表性原文与反例，再决定是否扩展。

用内置 [research_methods](../shared/local-methods.md) 完成可复用的全量读取、跨批实体去重、覆盖、标准分组及引用整理，再自由用 Python/SQL 比较、检查稳定性和可视化；一次组合独立计算，保存方法和样本范围。优先遵循已知 schema 和文件路径，复用已有冻结文件，不重复导出、猜字段或为原文引用回查同一条记录。Bash 无网络，联网走获准的原生 web 工具。没有统一身份就不推断跨品牌实际人群重叠；不同快照不能写成同一群体流失或增长。参考报告中的典型口吻和旅程若无原评定位，标为归纳或情境示意。详细方法见[研究方法](../shared/methods.md)。

遇到矛盾核对原文、版本、口径与定义，独立比较合理解释；证据不足就保留不确定性，不替底稿强行圆通，也不因局部问题否定整份报告。产品机会对应可见需求或约束，建议与已证实结论分清。

## 交付

按当前问题组织回答，清楚区分已有研究、新核查结果、本轮推断及待验证建议。给能改变决策的证据，不把工具流程写成用户研究结论。原问题证据充分、影响结论的矛盾已处理后即交付，不继续扩大品牌、样本或方法。直接用 DSH 最终回答；引用与文件说明见[交付](../shared/delivery.md)。
